# C-Scan Studio v3.6.0-beta.3 — 多磁盘压力回归与性能优化

独立预发布，不覆盖 v3.6.0-beta.2 和 v3.3.1。

## 回归驱动修复

1. 40,000 条合成记录、400 次分类分页，旧版重复访问 16,000,000 条记录；新版一次索引 + 分页读取，新扫描时丢弃旧索引。
2. 12 线程并发 240 次分页，旧版访问 2,880,000 条记录；新版在锁内共用只读快照索引。
3. 128–256 KiB 文件采样预算按照实际读取字节计算，不再把短尾块算作完整 128 KiB；确认重复仍要求全量 SHA-256。
4. 大量小目录进度回调节流：累计文件增加 2,500 个或间隔 0.5 秒才刷新；哈希阶段每新增 40 个全量校验文件刷新。

## 新测试与安全边界

新增 `tests_v363` 共 10 项标准库测试：40k 元数据、并发读取、快照更换、恶意盘符及分页参数、哈希边界、150 目录、文件数量上限、96 文件重复验证、取消扫描与版本一致性；原有回归测试和 Node.js 行为模拟继续运行。

- C 盘清理仍默认不选、服务端逐文件预览、一次性凭证并输入 DELETE。
- D–Z 盘只读分类/查重没有移动、删除或重命名接口。
- 模拟文件在 CI 临时目录生成和销毁，不触及用户真实磁盘。
- Windows 和 Ubuntu CI、CodeQL 对同一 GitHub 提交完成后才能发布 ZIP 和 SHA-256。
- **未验证实际 Windows 真实文件删除、USB 长时连接/断线或本版本 VirusTotal 结果**。

## 跨平台可重复构建修复

在新加的“构建前清单验证”中发现 Windows 的 Git 检出把大量文本文件转换为 CRLF，而 Ubuntu 保留 LF，使同一源码生成不同的 ZIP 和 SHA-256。

新增仓库级 `.gitattributes`：绝大多数文本用 LF、Windows 启动 BAT/CMD 在所有平台统一为 CRLF，PNG 保持二进制。发布包同时包含该文件，SHA-256 清单覆盖它。CI 新增跨平台 ZIP 摘要对比作业，**Windows 和 Ubuntu 完全一致才算 CI 成功**。

## Windows 回归触发的 HTTP 修复

压力 CI 中 Windows 偶发收到 `WinError 10053`：服务端拒绝跨域 POST 时立即关闭套接字，未读取的小请求体可引发 TCP RST，让客户端看到断线而不是预期的 403。现在只对小于等于 64 KiB 的已拒绝请求进行限时（0.5 秒）丢弃读取，**不会解析、信任或执行请求体**；新增 56 次并发恶意 Origin 请求，要求始终返回 HTTP 403 且从不触发清理。

## 固定 ZIP 字节的可重复构建

CI 跨平台摘要比对再次发现：即使文件内容和清单一致，Python 标准库 ZIP 在 Windows 与 Linux 使用的 `ZipInfo.create_system` 平台默认值也不同，DEFLATE 压缩还可能受 zlib 版本影响。发行工具现显式固定 ZIP 主机平台标识、权限、时间、附加元数据，并选择 `ZIP_STORED` 消除压缩算法差异。代价是源码包稍大，换取无需本机 Python 或 zlib 版本一致即可复算的 SHA-256。
