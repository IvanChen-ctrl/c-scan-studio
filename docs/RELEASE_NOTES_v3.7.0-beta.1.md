# C-Scan Studio v3.7.0-beta.1 — Unity 专项诊断与受保护清理

基于仓库最新功能版本 v3.6.0-beta.4，基线提交 `8c1dbd89c090c66b1c38b9f349d94242adcacb37`。本版针对“Unity 编辑器和工程在 D 盘，C 盘用户目录仍因缓存增大”的实际使用问题。

## 新增行为

- 独立 Unity 导航页与专项扫描，C 盘和其他盘的逻辑占用分开显示。
- 固定默认目录的 UPM、GI 与 14 天以上精确旧日志进入既有冻结快照预览流程；相关进程运行或检测失败时禁止清理。
- 离线包保护默认开启，UPM 缓存不预选；关闭保护后必须重新扫描，服务器独立校验。
- Bee、Asset Store、Hub 日志、Gradle 缓存与自定义配置路径仅供只读诊断。支持读取进程环境变量及 `.upmconfig.toml` 的根级 `cacheRoot`，不导出凭据。
- 限时、有条目预算、可取消的诊断；重复路径和硬链接不重复累加总占用。权限错误、路径变化和链接跳过均标明不完整。
- 普通 Temp 清理补充 Unity 工程标记、源文件类型和目录保护。缓存读取出现错误时，不再把部分结果标作可清理的完整扫描。
- Unity 清理不进入旧 CLI 一键清理；全部通过 Studio 的明确选择、逐文件预览和单次 `DELETE` 票据。
- 新增 Windows Runner 的便携 EXE 构建与冻结后本地 HTTP 自检；源码版继续保持零 pip 依赖。

## 回归驱动修复

进程枚举为空/异常时失败关闭；不可读目录不会显示为未找到；Windows文件身份从新鲜lstat读取；删除快照同时比较文件身份与元数据，拒绝相同大小和修改时间的文件替换；刷新页面保持实际离线保护设置一致。

本地 **304项Python + 20项JavaScript回归通过**，详见 [本地回归记录](VALIDATION_v3.7.0-beta.1_CN.md)。

## 验证边界

回归测试使用隔离临时目录和合成数据。测试会实际创建、改写与删除临时测试文件，覆盖删除边界、进程启动、过期快照和离线保护，但不会扫描或删除用户电脑的真实缓存。

Windows Runner 构建/自检证明程序能够在其 Windows 环境中打包并启动。它不能替代用户电脑中的 Unity 项目、网络下载和烘焙/构建验收。具体本轮测试结果与构建状态以交付报告和 GitHub Actions 对应提交记录为准。

本版保持 Beta，尚未执行用户电脑上的真实清理和 Unity 工程重建。目录联接、未读取的私有设置及自定义项目目录可能导致未覆盖的占用，工具会说明已读取范围。没有独立的本版病毒扫描结果，不沿用旧 ZIP 的检测结论。

## 上手

参见 [Unity 专项使用指南](UNITY_CLEANUP_GUIDE_CN.md)。完成清理后，优先通过 Unity/Hub 官方设置调整后续缓存与下载位置，避免反复清理后又写回 C 盘。
