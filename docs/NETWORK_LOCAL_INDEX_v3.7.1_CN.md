# C Scan Studio — 网络盘本地文件名索引（v3.7.1 候选）

## 为什么增加此模块

已有 `v3.3.1` 的 Everything/ES 模块主要搜索 C:；新版本 PR #14/#15 已支持 O: 等 Windows 映射网盘和无大小限制搜索，但 Everything 1.4 需人工在 `Tools > Options > Folders` 加入网络路径，且企业盘可能并未建立索引。

新增 `Network_Index.py` 在**不替换 Everything、不读取文件内容**的前提下建立独立 SQLite 元数据索引。用户已说明误传 HuzhuDesk ZIP；它仅提供少量数据持久化与失败恢复设计启发，**不是目标搜索引擎**。此后的 v3.7.x 回归升级已直接审阅用户提供的 **CoractiveFileFinder v1.21 Full Index Windows x64** 压缩包：完整 Go 源码位于 `source_go/fullscan.go`、`source_go/search.go`、`source_go/storage.go`，Go 原生测试已运行通过。HuzhuDesk 为误传，仅保留最少的工程启发。

## 操作（Windows 10/11）

1. **普通用户会话**运行 C Scan Studio；确认 Windows 资源管理器能打开 `O:\`。管理员会话可能无法看到普通用户映射的盘符。
2. 进入“**大文件快速搜索**”，选择 `O:` 或 `P:`，选择本机**固定盘 D: 等**作为索引保存位置。索引将储存于 `D:\CScanStudio_NetworkIndex\O_<映射身份摘要>.sqlite3`。
3. 点击“**建立 / 续扫索引**”，阅读机密路径提示并手动确认。默认以约 12,000 个目录项或 12 秒为一轮的**软预算**，但为了目录读取的原子性，会完整读取本轮已开始的一个目录，因此可能超出软预算。单目录超过 250,000 项会明确报错并保留待续扫目录，避免内存无限增长。结束后显示已发布文件、待发布文件、剩余待处理目录、是否完整。
4. 若提示“partial／尚不完整”，再次点击同一按钮继续。查询关键词 `Fab`、中文文件名、`.pdf` 或留空；所有大小的文件包括零字节文件均可索引。
5. 搜索优先使用经过 SHA-256 校验的 Everything ES；当其没有可显示结果时才读取用户选定本地磁盘已有的 SQLite 索引。不自动访问网盘进行增量同步，也不会据此触发清理。

## 使用范围与限制

- 仅支持当前 Windows 会话映射的 `D:...Z:` **DRIVE_REMOTE** 盘符；只读目录项的路径、名称、大小、修改时间，**不打开文件内容、不计算内容哈希、不删除网盘文件**。
- 索引库是**未加密的本地 SQLite 数据库**，路径和文件名可能属于内部信息；必须符合所属组织的数据存储政策。不要将其同步、发布到 GitHub 或与他人共享。
- 保存位置仅允许本地 D:～Z: **固定磁盘**，不写入 C:，拒绝链接/重解析的索引文件。软件不自动清空、迁移或覆盖历史数据库。
- v2 采用按目录完成后提交 `staged` 的持久事务，而不是继续复用 v1 不稳定的 `os.scandir` 偏移量。完整扫描完成前，**旧已发布文件条目保持不变**（可能过时）；新文件暂存 `staged` 并保留待扫目录队列。只有目录遍历结束才一次性原子发布新快照：遇到 ACL 不可访问的子目录或被保护的链接时，状态为 `partial_coverage`，结果可以搜索但**不能视为完整**；网络中断/取消则继续保留旧发布快照和待续扫队列。
- 目录可能在扫描时变化，因此完整标记只说明该轮遍历结束，不代表实时一致；索引中展示的文件可能已被修改、移动或删除。单次网络 I/O 阻塞可能导致实际等待超过预算。
- 避免在超大企业共享盘上频繁全量索引。首次扫描需遵守网络管理员和共享盘使用规范。缓存不自动定期更新；必须手动再次点击。
- 如果是 UNC 路径索引、WebDAV、OneDrive 或某些不标准虚拟盘，可能无法识别为映射网络盘；不得绕过盘符/身份检查。

## 安全验证与真实测试

本项目测试只使用自有临时文件和模拟 Windows 映射盘，覆盖明确授权、无 C 盘数据库写入、索引断点续扫、零字节文件、中文/ASCII 文件名、文件符号链接拒绝、SQLite 链接拒绝、部分扫描保存、缓存优先级与取消保护。真实企业 O: 实机访问、服务器限流、Windows 映射身份、网络 I/O 阻塞仍需独立验收。

## CoractiveFileFinder v1.21 源码对照与迁移范围（本次回归）

直接读取上传的 `Coractive_FileFinder_v1.21_Full_Index_Windows_x64.zip`，校验 ZIP CRC 成功。**未执行未知来源的 Windows EXE，也未接触真实公司 O: 网盘。**

| Coractive 源码 | 实测设计 | C Scan 本轮实现 |
|---|---|---|
| `source_go/fullscan.go` | 每个目录完整读取成功后写入检查点；被取消目录重新扫描，避免不稳定枚举顺序 | SQLite v2 按目录提交 `staged`，不再持久化目录枚举 offset |
| `source_go/fullscan.go` | 新索引通过本地完整提交后才发布；旧索引保持可搜索 | SQLite 原子事务发布，断线/取消/磁盘写入失败保留旧 `files` |
| `source_go/search.go` | 基于文件名 trigram 倒排候选，加速子串查询 | SQLite FTS5 trigram 的 GLOB 字面量查询；不支持时回退 `instr()` |
| `source_go/model.go` / `source_go/storage.go` | 缓存版本与已有快照复用 | 对既存 SQLite v1 做保守迁移；旧偏移队列全部重新检查 |
| `source_go/fullscan.go` | ACL、跳转链接和受限目录明确标注不完整 | 增加 `partial_coverage`、`skipped`、`coverage_errors`，不虚报完整 |

**没有原样移植 Go 源码**。两者索引格式不同：Coractive 使用 Go 日志 + gzip JSON，C Scan 采用磁盘型 SQLite，更适合超过原来 50 万条限制的长期索引。FTS5 并非所有 SQLite 构建都可用，因此仍保留普通搜索。

**保护边界：** 此轮增加目录原子性后，12 秒/12,000 项是目录之间的软预算；单目录最多 250,000 项以限制内存。索引可能未经加密地保存企业敏感文件名，用户必须获得授权、保存于受控加密本地磁盘；不能把这个数据库提交 GitHub、邮件或网盘同步。测试为合成共享盘；实际 Windows SMB/DFS 和安全软件环境尚未验收。
