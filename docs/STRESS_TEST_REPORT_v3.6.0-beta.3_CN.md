# C-Scan v3.6.0-beta.3 压力测试记录

## 红灯阶段：可复现失败

CI: https://github.com/IvanChen-ctrl/c-scan-studio/actions/runs/41248785703

| 场景 | 输入 | 旧代码的实际结果 |
| --- | --- | --- |
| 分类分页重复遍历 | 40,000 条合成数据，400 次请求 | FAIL：访问 16,000,000 条记录，目标不超过 80,000 |
| 线程并发分页 | 12 线程，240 次请求，12,000 条记录 | FAIL：访问 2,880,000 条记录，目标不超过 24,000 |
| 文件哈希边界 | 128 KiB + 113 字节，预算等于实际采样量 | ERROR：错误提示采样预算不足 |
| 150 个小目录进度 | 150 目录，每个一个小文件 | FAIL：发送 60 次进度回调，限制 12 |

Windows 和 Ubuntu 的同一次 CI 均重现上述三项失败、一项异常；另外五项测试通过。

## 代码修复与验收方式

- 分类快照只读索引：按 (category, subtype, volume) 四种通配组合聚合，锁内初始化，快照更换时清空，保持过滤校验与分页范围限制。
- 修正 SHA-256 首尾采样预算误差。没有减少完整内容哈希要求。
- 加入文件数或时间节流，防止小目录扫描时大量重复推送 UI 进度。
- 新增版本一致性测试，统一 UI、后台与发行包为 v3.6.0-beta.3。

验收不依赖硬件的绝对耗时（CI 虚拟机有差异），而以访问总次数、文件数预算、SHA-256 完整性、请求成功率与只读安全边界为断言。绿色结果必须以最终提交的 Windows/Linux CI 与 CodeQL 为准。

## 范围限制

这些回归使用 Python 临时文件和合成内存文件目录，不是对用户真实 C 盘或 D/E 盘执行长时间压力运行；也没有测试 NTFS 实际权限/联接点的所有组合、机械磁盘健康、USB 物理断线。源码完整性清单不是杀毒认证，发行 ZIP 需独立进行 VirusTotal 核验。

## 跨平台 ZIP 哈希失配诊断与修复

早期 Beta 的 Windows 与 Ubuntu runner 曾从同一提交产生不同 ZIP 哈希，原因是平台依赖的 Git 文本换行符策略。以前各自单独通过 CRC/manifest 的检查无法识别这种非可重复性。

已加入 `.gitattributes` 明确统一 LF 文本、Windows BAT/CMD CRLF，在两种操作系统中检出相同字节；增加独立 CI 作业比较 Windows/Ubuntu 产出 ZIP 的 SHA-256。必须两方相同才通过。此检查不替代第三方恶意软件扫描。
