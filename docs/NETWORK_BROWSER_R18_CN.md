## 源码依据及与参考项目的关系

本轮从用户上传的 `Coractive_FileFinder_v1.21_Full_Index_Windows_x64.zip` 阅读了：

- `source_go/search.go`：`parseQuery()` 的普通词、引号、`name:`、`path:`、`ext:`、`type:`、`-排除`；trigram 预筛选及全局确定性排序。
- `source_go/folder_view.go`：从**本地已发布索引**构造文件夹树、直属/子级文件计数和可分页文件列表，不让“文件夹浏览”悄悄重新扫描共享盘。
- `source_go/filter_paging_v18_test.go`：筛选必须在分页之前生效，避免“前 180 条没有匹配就被判为找不到”。

没有原样复制 Go 实现或运行参考包里的 Windows EXE。C Scan 使用原有 SQLite 快照和官方 Everything 搜索引擎，二者数据格式不同，按行为重新实现。

## 新功能

1. **组合文件名查询**：留空搜索全部，普通词与 `name:` 是文件名子串；`path:` 是完整索引路径中的字面片段；`ext:pdf` 为扩展名过滤；`-draft` 排除名字或路径包含 draft 的文件；`type:file` 为显式文件筛选。引号将多个词视作一个词组，例如 `name:"annual report" ext:pdf -draft`。
2. **完整总数与分页**：从已发布 SQLite 数据库计算正确总匹配数，应用过滤条件后再取第 N 页，不再只筛已返回的 180 条。默认每页 100 条、最大 200 条，最大 offset 1,000,000；文件搜索按大小降序及路径稳定排序，避免等大小导致分页重复。
3. **真正的文件夹目录**：扫描成功发布时，在同一个 SQLite 事务里生成 `folders` 目录表。显示空目录、直属文件数及含子级总数；点击文件夹后显示直属文件或递归文件。文件夹列表和文件分页都在本地数据库完成，不访问网盘。
4. **刷新隔离与失败保护**：新快照未完成时，`files` 与 `folders` 两张旧已发布表维持一致。发布失败时 SQLite 事务回滚两者，旧文件夹计数和搜索结果不变。此前 v2 的未完成目录偏移队列会保守重新扫描，不会假装已有空目录可用。
5. **路径和会话保护**：仅从已索引目录表选择合法根目录相对路径，不能经 `../`、UNC 或任意路径触发读取；HTTP GET 仍需本地会话 token、严格盘符/索引磁盘校验。前端切换盘符自动清除旧盘的文件名和路径，异步过时响应不显示。
6. **旧版本兼容**：原有 `Network_Index.lookup()`、Everything 索引查询、Windows 便携版打包与清理保护都保留。旧 SQLite v1/v2 文件表仍可查询；首次完成新的目录级快照后才能使用文件夹树。SQLite 缺少 FTS5/trigram 时自动使用普通子串搜索，不会因此要求第三方程序。

## 使用步骤（Windows）

1. 打开 C Scan → “大文件快速搜索”；选择 O:、P: 等 Windows **已映射**网盘，再选择 D: 等本地固定盘保存索引。
2. 如本地索引未建立，必须自己点击 **建立 / 续扫索引**，阅读文件名可能涉密的提示并确认。扫描只存路径、文件名、大小和修改时间，不打开文件内容。
3. 使用页面下部 **Coractive 风格 · 本地索引文件浏览器**，输入 `Fab ext:pdf path:docs -temp` 等表达式，然后点击“查询所有已索引文件”；用“上一页/下一页”翻页。
4. 点击“浏览文件夹”，从根目录进入各子目录；可选择是否将子目录文件包含在列表中。**浏览本身不发起网络扫描。**
5. 如看到 `partial` / `partial_coverage`，表示旧快照不完整或正在更新，结果不代表共享盘全部文件；可以在完成授权后再次扫描刷新。

## 未解决的边界

- 企业 O: 的真实 SMB/DFS 访问权限、文件名编码、延迟、断线重映射、服务器负载均未实机验证；这是跨平台模拟回归而不是“真正网盘已验收”。
- 浏览索引仍需当前 Windows 会话能确认映射盘目标身份；**网盘完全断开时尚未加入“明确选择旧快照身份”的离线模式**，不会为了方便而混用 O: 盘符历史上属于不同共享盘的数据库。
- 索引并非实时同步；旧记录可能已经移动/删除，必须在用户手动重新授权扫描后刷新。
- 本地 SQLite 保存未经应用级加密的敏感文件名和路径。请把存储磁盘交给组织允许的受控加密存储，勿上传 `.sqlite3`、敏感搜索记录或企业共享盘数据到 GitHub。
- 目录表发布时占用与不同目录数量成比例的临时内存；目录极多的共享盘需在后续用真实数据进行性能压测。
- 过滤条件是“与”关系（全部满足），目前没有 OR、布尔分组或按时间范围的高级过滤，不应宣称完全复刻 Coractive。
